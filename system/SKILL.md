# 修行面板 · AI 层说明书

> 这是给 **Claude Code** 看的规程。确定性的事（建库、算道痕、渲染）由 `*.py` 做；
> AI 只做**判断类**的事：抽取、分类、诊断、拟今日一炼。

---

## 每天怎么用

```
1. 在 data/ 里写记录（.md，沿用你原来的随手记习惯，不必改格式）
   —— 或者干脆 `python run.py 记 "..."`，一条命令替你放对位置
2. 对我说：「跑今天的」　（等价于 `python run.py`，不带参数就是它）
3. 我做五件事 → 你看 panel.html
```

**用户的硬要求（2026-10-16）**：「**顺手的意思就是越简单越好，尽量不要让用户有多余的动作和操作。**」

推论，做任何新功能之前先过一遍这条：
- **能算出来的，不要让人填。** 心力默认就是推出来的，自述只是可选的覆盖。
- **能一步的，不要两步。** 所以 `python run.py` 不带参数跑完整条链，而不是让人记四条命令的顺序。
- **能复用的入口，不另开一个。** 网页面板是同一个事实层的壳，不是第二套系统。

## 我（AI）每天要做的五件事

### ① 抽取
读 `data/` 下新增的记录，抽出证据条目。每条产出：

```
(ts, text, source_type, [(道, 权重), …])
```

**`source_type` 只能取这五类**（见基准文档 §1.5）：

| 类型 | 计痕 |
|---|---|
| `产出` | 方案 / 方法论 / 作品 / 结论（**含 AI 协作产出**）→ 1–3 |
| `踩坑` | 从实际试错中得出的规则 → 0.5–2 |
| `协作` | 参与，即使他人主导（"协作增加经验，推动道行"）→ 0.1–0.5 |
| `学习` | 消化过的输入（**含搬运整理**）→ 0.1–0.5 |
| `愿望` | 想做但没做 → **0（记缺口，不入证据）** |

**「学习」的边界（用户 2026-09-24 定）**：判据不是"自己悟的／别人讲的"，
而是**"是不是在做事的当口得到的"**。

> "其实都是，这些都是我在做项目时得到的知识和产生的疑惑"

所以：在项目里听来的（培训、同事讲的）、查到的（OCP 建模特性）、
撞出来的（DFR 是什么？为什么 media 会影响对比值）——**都算学习**。
只有脱离实践情境的纯摘抄才不算。**别用"自悟才算"去筛，那会误杀一大片。**

### ② 归属
一条证据可同时归属**多道**，**权重按分配、总和守恒**。
  - 例：一条 1.0 的证据若同属炼道与智道 → 各 0.5

### ③ 诊断
- **两轴**：修为（精力/时间/容量）vs 道境（各道境界）
- **缺口**：哪条道饿着、哪条道的晋升事件已接近达成
- **组合**：哪几只蛊可以合炼（杀招）
- **选杀招铁律：兴趣优先于成本**（可投入的精力有限时，兴趣是最可持续的燃料）

### ③b 读心力

**真元 ＝ 心力 ＝ 一段时间内能做完的事的量**（件），分「日」「周」。口径见基准文档 §1.6。

- **默认用推演值**：该周期内 `产出`＋`踩坑` 的证据条数。**不让人填**——记录里本来就有。
- **自述覆盖推演**：用户说了数就用他的。`run.py 心力 12 周 无波`。
- ⚠️ **面板上两种来源必须看得出区别**：推演是**下限**（不记就不算），
  绝不能让它冒充人说的数。措辞写死成「按记录推 · 不记不算，是下限」。
- 诊断时**看趋势，不看单点**（心理只做趋势）。一个点画不出趋势——
  若只攒到一个点，直说「还看不出趋势」，不要编。

### ④ 拟今日一炼
**每天只给一件事**，且必须：
- 放在**早上**（用户精力高峰）
- 带一个 **5 分钟版**（低状态日也能完成）
- 优先喂**既饿着、又是重要母道**的那只蛊

### ⑤ 同步知识库（kb/）

**面板回答「我现在该干什么」；知识库回答「我知道什么、还缺什么」。**
抽取完新证据，知识库就该跟着走一步——否则它只是一份越来越旧的快照。

**每次 ingest 之后做这四件事**（用户 2026-10-16 定为常设工序）：

1. **新知识入库**：把新证据里属于「可复用的知识」的，写进对应领域篇（`kb/01`–`08`）。
   判据不是"重要不重要"，是**"换个项目还用得上吗"**——一次性的项目细节不进库，
   方法、规律、坑才进。
2. **答掉的空洞**：把该篇末尾「待补空洞」里已经答掉的移走，
   并把对应的 `Q｜` 升级成 `术语／理论／做法`。
3. **新踩的坑**：写进对应领域的「坑」，**现象 + 应对**两段都要有。
4. **重新生成星图**：`cd kb && python build_starmap.py` → `星图.html`。
   星图是从 `.md` 现算的，**不手改**。

**入库的硬规矩**：
- **每条都标出处**（哪个文件、哪一天）。**指不回去的不收。**
- 宁可写「**还没查到**」，也不留空标题——`记事本碎.txt` 里那个空的 `## 2. dfr`
  就是这么来的，问题记下了、答案没回来。
- **新的疑问**照样用 `Q｜` 记下来，**哪怕答案是"还不知道"**。
  问题本身就是资产：它标出你知识体系的边界。

## 面板的信息分级（哪些露、哪些收）

用户 2026-09-24 定的：**「信息只在该出现时出现，或者互动时出现，不要都一股脑出现。」**

一股脑摊开的结果是——**真正要你做的那件事，会被四十行参考信息淹掉**。
所以除下面三项外，一律默认收起（`section(..., folded=True)`，原生 `<details>`，零 JS）：

| 默认可见 | 为什么 |
|---|---|
| 称号 + 两轴 + 空窍读数 | 我是谁、什么状态 |
| **今日一炼** | **今天做哪一件——这是整页唯一的行动** |
| 诸道（含各自「下一级」） | 我什么水平、往哪走 |

其余全部收起：晋升阶梯（全 48 级）、记下的缺口、饱食的蛊、其余杀招、道痕明细。

**收起的规矩：摘要行必须自带结论**，否则「收起」就变成「藏起来」。反例与正例：

- ❌ `晋升阶梯` —— 光一个标题，用户不知道值不值得点
- ✅ `晋升阶梯 · 8 道 × 6 级 · 下一级见上表` —— 想点就点，不点也知道有什么
- ✅ `所养之蛊 · 3 只饿着 · 人言蛊濒死、役智蛊微饥、准绳蛊微饥`
- ✅ `道痕明细 · 共 65 条 · 最近 2026-09-24 · 每条可溯源`

两条推论：
- **饿着的蛊露出来，饱食的收起来**——不饿的蛊今天不需要你关心。
- **杀招只亮首选一记**——今日一炼已经给了「做哪一件」，四记并排又变成四个方向，
  而用户的瓶颈恰恰是「懂却做不动」。

## 晋升门槛怎么写（阶梯，不是口号）

每一道有**六级门槛**，写在数据库 `proof_ladder` 里，索引 1–6 对应「升到大师…升到道主」。
面板默认只亮出**下一级**那一格。

**铁律（用户 2026-09-24 指出）：门槛必须是「下一件你够得着的事」，不是终极理想。**

> 反面教材：智造道原本把「造出东西能自己思考」当成**大师**的门槛——
> 那是全世界没人敢说做到的事。这样写，等于这道永远不可能晋升。

递进骨架，逐级往外扩：

| 级 | 骨架 |
|---|---|
| 大师 | **第一次做到**（本月就可能达成） |
| 宗师 | 被复用 / 被看见 |
| 大宗师 | 脱离你也能跑 |
| 准无上 | 跨领域仍成立 |
| 无上 | 别人照你的做（开宗） |
| 道主 | **开创**（终极使命放这里，不放前面） |

写新门槛时自查一句：**"这件事我这周做得到吗？"** 答否，就说明它不该在这一级。

## 五条硬规矩（不可违反）

1. **境界不可自评**。只能由「达成事件」触发，且**必须用户确认后**才写入 `realms_log`。
2. **事实层不可虚构**。每条证据必须能指回原文；指不回去的，宁可不记。
3. **心理只做趋势**。不打分、不诊断、不替代专业帮助。
4. **面板上的字，凡是能被数据算出来的，一律现算，不准写死。**
   写死的文案一定会过期：改了数据、面板还说的旧话，用户就会不再信这个面板。
   - ✅ 写死在模板／seed 里的，只允许是「人的判断」——你的推理、语气、命名。
   - ❌ 不许写死：「哪只蛊最饿」「哪条道最浅」「当前是几转」「下一个境界叫什么」。
   - 自检：`python run.py selftest`（改数据，面板必须跟着变，6/6 才算过）。
     新增任何一处会过期的文案，就往 `run.py` 的 `CASES` 里补一条用例。
   - ⚠️ **过检 ≠ 没病**。曾经 4/4 全过，页面上却写着「火候蛊已『饱食』……是眼下最饿的一只」——
     因为 `CASES` 里从来没有「最饿的那只没写练法」这条。
     **每加一句比较级（最饿／最浅／最快），先问：这个比是查出来的，还是我顺手写下的？**

   > 这条规矩是踩出来的：曾经 今日一炼 的标题从数据来了、描述却是写死的，
   > 于是标题说「人言蛊」、描述还在讲上一次考核认证——**标题和正文互相打架**。

5. **确认证据是「人」的动作，AI 不得自行确认自己抽的东西。**
   只有用户明确说了（如「没有疑虑的直接更新」）才能跑 `run.py confirm`。
6. **重建不得抹掉「人的决定」。** `rebuild` 会清空 evidence 表，但用户已确认的证据、
   已判定的愿望、改过的道痕分配、喂过的蛊，**以及晋升流水**，都属于用户数据。
   `rebuild` 拍五份快照再贴回：
   `(ts,text)` 与 `ext_key` 两套确认键（后者兜住**正文会漂移的外部回执**）、
   外部条目的分配（只贴 `alloc_edited=1` 的，即人真的改过的）、`gu.fed_at`、
   **`realms_log`（按道名存，重建后 dao_id 会重排）**。
   改 ingest 时若删改条目，注意旧确认会因原文不存在而失效（命令会报出来）。

   > 这条踩过两次。第二次是 `realms_log`：**晋升是这系统里最纯的「人的决定」**
   > （硬规矩 1 说境界不可自评，只有用户亲口给的事件才算数），
   > 却唯独它没进快照清单——`promote` 之后一 `rebuild`，境界静默回滚到普通，
   > 而面板上还写着「重建不抹人的决定」。
   > 现已补上，并在 `check()` 里加了一条不变式：**`realm_index` 必须等于晋升流水的最后一笔**
   > （境界不另存一份真相，两者不可能各自漂移）。

> **愿望**（`wishes` 表）：想做但没做 → **0 道痕，不入证据，但记下缺口**。
> 缺口本身是重要信息——「道境高于修为，懂却做不动」这个诊断，靠的就是看见缺口。
> 判定存疑时问用户，别自己猜：曾有一条「关注某数据分布形态」被当成产出，
> 用户判定是愿望。

## 阈值速查

| 项 | 值 |
|---|---|
| 道境七级 | 普通 → 大师 → 宗师 → 大宗师 → 准无上 → 无上 → 道主 |
| 蛊饿死 | ≤2周饱食 ｜ 2周–1月微饥 ｜ 1–3月饥饿 ｜ 3–6月濒死 ｜ >6月沉睡 |
| 蛊师阶段 | **只能持有凡蛊**；仙蛊名不可用于自身之蛊 |
| 道痕 | **宽**（含别人带着你走的）｜ 境界 **严**（只认你自己打出来的） |

### 蛊的饥饱是**推出来的**，不是写死的

`gu.state` 由 `gu.fed_at`（上次炼是哪天）按上表推出，回写在每次 `rebuild`/`feed` 时刷新。
**不要直接改 `state`** —— 那是把一个算得出来的值写死（硬规矩 4）。

- 「炼了一次」由 `run.py feed <蛊名>` 或网页面板的「炼了」按钮写入 `fed_at`
- `fed_at` 为空 → 推不出来，保留 seed 里的字面值。
  **这不是偷懒**：老库里的 state 是当初写下的判断，凭空给它编一个喂养日期
  等于伪造一条事实（硬规矩 2）。等它真被喂过一次，推导才接管。
- `fed_at` 是「人的决定」，`rebuild` 会按 `snapshot_gu_fed` 保住它。

## 命令

```bash
python run.py            # ★ 跑今天：重灌 → 抽新证据 → 出面板 → 自检 → 打印该看的几行
                         #   （不带参数就是它。中文别名：今日/跑/看/检/面/炼/升/记/心力/确认/测）
python run.py 记 "今天做了什么"    # 顺手记 —— 追加到 data/task.md 的当天段落
python run.py 心力 12 周 无波      # 记一条自述读数（不记也行，面板按记录推一个下限）
python run.py check      # 完整性自检：信息无断链 + 道痕守恒 + 境界与晋升流水一致
python run.py status     # 看道痕（已确认／待确认分列）与蛊的状态
python run.py render     # 重新出面板
python run.py rebuild    # 重置 → 灌数据 → 追加新证据 → 出面板 → **自动跑 check**
                         # 自检不过则退出码非零，并在末尾标出是哪一项
python run.py selftest   # 回归测试：改数据，面板必须跟着变
python run.py confirm    # 确认全部待确认证据（须用户授权）
python run.py confirm 61 # 确认除 id=61 之外的全部
python run.py feed 人言蛊 # 炼过一次 —— 记下日期，这只蛊的饥饱由日期推出来
python run.py promote    # 列各道的下一级门槛（只读）
python run.py promote 星道 "你达成了什么事"   # 晋升一级（须用户判断，见硬规矩 1）
python run.py web        # 起网页面板 http://127.0.0.1:8765
python run.py init       # 重置（会清库，慎用）
```

网页面板（`web.py`，标准库，无新依赖）提供三件事：**随手记**（写进 `data/收件箱.md`）、
**勾选确认**证据、**刷新即见**最新数据。它只加一层可点的壳，不改事实层——
关掉它，上面的命令一样跑。

**为什么 `rebuild` 要自带 check**：道痕守恒、标签配对这类问题，**页面照常显示、不报错**，
人眼根本看不出来。这个系统里已经出现过的两个 bug（写死的文案过期、漏一个 `</div>`
导致整页样式错位）都属于这一类。**跑通才算跑通——不能靠"看着没问题"。**
