# 个人成长系统

把日常记录变成两个东西：一张**修行面板**，和一张**知识星图**。

面板回答「我现在该干什么」；星图回答「我知道什么、还缺什么」。两者共用一套世界观设定，但**代码和数据是分开的**——这个仓库只装代码。

---

## 快速开始

```bash
cd system
python run.py init      # 建库 → 灌入示例数据 → 生成 panel.html
```

打开 `panel.html` 就能看到面板。

想边用边记、边确认证据，起个本地服务：

```bash
python run.py web       # http://127.0.0.1:8765
```

只依赖 Python 标准库，不需要装任何东西。

## 命令

**日常只有一条**：`python run.py`（不带参数＝跑今天：重灌 → 抽新证据 → 出面板 → 自检 →
打印该看的几行）。中文别名与英文等价。

| 命令 | 作用 |
|---|---|
| **（无参数）** | **跑今天** —— 日常就用这一条 |
| `记 "..."` | 顺手记一条，追加到 `data/task.md` 的当天段落 |
| `心力 12 周 无波` | 记一条自述读数（**不记也行**，面板会按记录推一个下限） |
| `init` | 首次建库 + 渲染 |
| `render` | 只重新渲染面板 |
| `rebuild` | 重灌数据 → 重新渲染 → 跑完整性自检（**不抹掉你已确认的证据与晋升**） |
| `check` | 完整性自检：孤儿证据、道痕守恒、境界与晋升流水一致、HTML 标签配对 |
| `status` | 各道道痕与各蛊状态 |
| `confirm` | 确认待定证据，之后才计道痕 |
| `feed 人言蛊` | 炼过一次 —— 记下日期，饥饱由日期推出来 |
| `promote 星道 "达成了什么"` | 晋升：**由达成事件触发，不可自评** |
| `web` | 起本地服务（随手记 / 记心力 / 确认证据 / 点「炼了」） |
| `selftest` | 改数据 → 断言面板跟着变 → 还原（6 项全过才算） |

别名：`今日 · 跑 · 看 · 检 · 面 · 炼 · 升 · 记 · 心力 · 确认 · 测 · 建`

星图单独生成：

```bash
cd kb
python build_starmap.py   # → 星图.html
```

## 数据放在哪

**这个仓库里没有你的真实数据，也不该有。**

| 位置 | 内容 | 入不入库 |
|---|---|---|
| `data/` | 你的真实记录、基线数据、外部源登记表 | ❌ 已被 `.gitignore` 挡住 |
| `demo/` | 脱敏示例（基线 + 示例回执） | ✅ 入库 |

**两个读取口，都是「有真的用真的，没有回落到 demo」**：

| 读取口 | 真 | 示例 |
|---|---|---|
| `system/baseline.py` | `data/baseline.json` | `demo/baseline.json` |
| `system/receipt.py` | `data/sources.json` | `demo/sources.json` |

跑起来时输出里会写明用的是哪一份（`证据来源：data/baseline.json（真实记录）`）。

所以空 clone 直接 `python run.py` 就能跑出一个有内容的示例面板，
**连「别的仓库 → 回执 → 面板」那条路也是通的**（示例回执里有 strategy 与 prediction 各一条）。
把你自己的记录放进 `data/baseline.json`、外部源登记进 `data/sources.json`，它就变成你的。

### 基线数据的格式

`demo/baseline.json` 就是模板，照着写即可：

```jsonc
{
  "evidence": [ ["2026-01-08", "做了什么", "产出", [["律道", 0.5]]] ],
  "new":      [ ["2026-05-25", "待确认的记录", "产出", [["炼道", 0.3]]] ],
  "wishes":   [ ["2026-05-27", "想做但没做", "为什么算愿望"] ],
  "moves":    [ ["杀招名", "状态", "需要的蛊", "人的判断", 1] ],
  "profile":  { "cultivation": "一转", "capacity": "稳定" },
  "aperture": [ ["2026-05-28", "week", 12, "平稳", "稳定"] ]
}
```

- `evidence` / `new` 每条 = `(日期, 文本, 来源类型, [(道, 权重)…])`，日期可为 `null`
- 来源类型取 `产出 / 协作 / 学习 / 踩坑 / 愿望`；权重单位是道痕
- `moves` 的 note 写「人的判断」——凡是能被算出来的（哪只蛊最饿、哪条道最浅）一律不写死，交给 `render.py` 现算
- `aperture` 每条 = `(日期, "day"|"week", 心力件数, 心境, 精力)`。
  **不写也行**——心力默认由记录推（该周期内 `产出`+`踩坑` 的条数），自述只是覆盖，
  且面板上会标明哪个是人说的、哪个是算的（推出来的是**下限**）

### 外部源登记表的格式

`demo/sources.json` 是模板。它登记「去哪儿取回执」，回执本身由**别的项目**生成：

```jsonc
{ "sources": [ { "name": "示例·回测", "kind": "receipt", "path": "demo/receipt_demo.json" } ] }
```

`path` 相对本仓库根目录；**真实登记表里可以写绝对路径或 `../` 指向兄弟仓库**——
本机路径只允许出现在那里（`data/` 不入库），代码里一个都不许有。

回执条目两种，形状见 `demo/receipt_demo.json`：
`strategy`（跑出了什么）与 `prediction`（写下什么判断、会被什么推翻、结果如何）。
**装载器只校验形状**；道名、蛊名是否存在交给数据库判——唯一真相在库里，不在文件里。

**代码里只有机制，没有内容：**

| 放哪 | 是什么 |
|---|---|
| `system/seed.py` | **结构设定**：八道、蛊、晋升阶梯、杀招的材料构成 |
| `baseline.json` | **个人内容**：证据、杀招的判断、自评、读数 |

分界线是「换个人还成立吗」——八道的名字换个人也这么叫，但一句针对某个具体的人的判断，只对那一个人成立。
后者一律进 JSON，代码里不留。

> ⚠️ **一处已知的缝合线**：`seed.MOVE_GU` 是结构（哪几味蛊合炼哪一记），
> 但它**按杀招的名字索引**——而名字是内容。所以代码里加一记、某份 baseline 没跟上时，
> 两边就会错位。已经改成**求交 + 跳过 + 报出来**（不再崩），但这仍是「结构」与「内容」共用一把钥匙。
> 真要让开，得把蛊的构成从代码挪进 JSON，和 `materials` 那个字符串合并成一处。
> 暂时留着——**知道它在哪，比装作没有强。**

## 几条设计原则

这些不写在注释里容易忘，所以放这儿：

1. **能被算出来的，就别写死。** 哪只蛊最饿、哪条道最浅、今日炼什么——全部现算。写死的文案一定会过期。
2. **验证靠「改数据看输出跟不跟」，不靠人眼看一遍。** `run.py selftest` 就是干这个的。
3. **境界不可自评，由达成事件证明。** 门槛必须是「下一件够得着的事」，不是终极理想。
4. **缺口要显式显示，不能隐藏。** 记下的缺口、待补空洞、还没有对应知识域的道——都是信息，藏起来才是错。
